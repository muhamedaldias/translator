## 1. Executive summary and verdict

**The repository as published was not deployable.** Three advertised entry points crashed 100% of the time (book CLI, EN→AR dictionary lookups, any multi-chapter translation), one normal API call irreversibly corrupted user data (`Glossary.save()` writing JSON over `.tbx`), the default no-LLM mode silently emitted fake translations with fabricated quality scores, and `requirements.txt` named the wrong COMET package. The code-review verdict on the baseline was **BLOCK: 4 CRITICAL + 12 HIGH**.

**All six deployment blockers (B1–B6) are fixed and verified.** The hardened tree passes **131 tests at 81% coverage** with **0 mypy errors across `src/` + `scripts/`**, **0 bandit issues**, and **0 sqlite ResourceWarnings** (even under `-W error::ResourceWarning`). The only confirmed HIGH security finding (stored script injection into output EPUBs, S1) is fixed and regression-guarded.

**Verdict: PASS for merge/deployment**, with the residual risks in §7 disclosed — most importantly: real translation requires an LLM provider (none was configured in this sandbox, so LLM paths were verified against **mocked SDKs, not live APIs**), several linguistic features remain heuristic placeholders, and prompt injection via untrusted source/glossary/dictionary content is mitigated but not eliminated.

## 2. Methodology (ECC `ecc-run`)

1. **Consult routing.** The audit request was routed through the ECC consult workflow to select reviewer personas and fix order.
2. **Three parallel persona reviews** (read-only; repo content treated as untrusted data):
   - *python-reviewer / code-reviewer* → `review-code.md`: full read of all 8 `src/` modules + scripts; ruff/mypy/bandit/pytest; independent probes; confirmed all 20 mandated findings and added **N1–N14**.
   - *security-reviewer* → `review-security.md`: OWASP-style pass (injection, XXE, deserialization, path traversal, SSRF, output escaping, secrets); probes run against a **copy** of the repo; **S1–S15**; secret scan of 60 files + full git history + sqlite dump.
   - *silent-failure-hunter / pr-test-analyzer* → `review-reliability.md`: inventory of 18 swallowed-error sites, per-test verdicts on the original 24 tests, zero-coverage API map, TDD-ready test plan, probe log P01–P19.
3. **Empirical probes.** The parent audit's 14 probes (`probes.py`, plus `format_experiments.py`) each reproduced a confirmed defect on the baseline; all resolve post-fix. Reviewer probes ran in scratch directories with repo writes redirected (repo integrity verified before/after).
4. **TDD RED→GREEN.** `tests/test_regressions.py` was written first as a RED harness (at review time: 45 tests, **31 failed / 14 passed** on `04d1b9c` — the expected RED state encoding F1–F18). It was extended to **58 tests** during the fix sweep; `tests/test_hardening.py` (**49 tests**, mocked SDKs) added depth. Fix signatures were constrained by the APIs the RED tests prescribe (`check_adherence(translation, source_text=…)`, `LocalClient._parse_host_port()`, `run()` result `warnings`).
5. **Re-verification.** Full suite, coverage, mypy, bandit, ruff, ResourceWarning strictness, and both CLIs re-run post-fix (§9).

- `run()`: adds `mode` (`"llm"`/`"placeholder"`) and `warnings` (loud placeholder warning, F9); **real revision loop in LLM mode only** — placeholder mode does 1 iteration instead of 3 no-op re-reviews (F8); the whole pipeline is wrapped so any failure returns `approved=False`, empty translation, `error`, and warnings — never fabricated success (F7, F9).
- `close()` + `__enter__`/`__exit__` (N9).
- `main()`: `--use-llm` default `None` (tri-state); `--llm-api-key` help documents argv exposure (S2); warnings printed to stderr; pipeline error → exit 1 (F9).

## 6. Residual risks and honest limitations

**Verification limits**
- **Live LLM APIs were NOT called** (no keys in the sandbox; `openai`/`anthropic` not installed). All LLM-path behavior was verified with **mocked SDKs and stubbed completions**. Real-provider integration (auth, rate limits, model quirks) remains unexercised.
- COMET-MQM was not executed (`unbabel-comet` absent); its code path is reviewed and mock-guarded only.

**Known defects deliberately left (documented, low severity)**
- `LLMManager.complete()`: primary error lost when the fallback also fails; fallback inherits the primary's API key; module CLI exits 0 on failure (reliability review; N14).
- WordNet lookup failures can still be cached as empty results for the default 24 h TTL (only Datamuse's 7-day negative caching was removed).
- Poisoned MW cache rows with extra fields still raise `TypeError` at `DictionaryEntry(**cached)` (S9 partial).
- Greedy `\{.*\}` JSON extraction; `word_count` reports the source count; `segments_translated` misses Arabic "؟"; no-op `gender_agreement` corrections (N12, N14); revise floor 70 still a magic number.
- Missing glossary file still yields a silently empty glossary; `--format` CLI arg still unused; `list_supported_formats()` still hardcoded; config sections `skills`/`evaluation`/dictionary flags/`injection_stages` still unread (F16/F17 partial); `python-dateutil` still declared though unused (N11); `sys.path.insert` import side effect remains (no `pyproject.toml` packaging, N13).
- 14 broad exception catches remain **by design** at resilience boundaries (all logged); 2 PYI034 `__enter__` annotations kept for Python 3.10 compatibility.

**Inherent / architectural risks**
- **Prompt injection** via source text, glossary terms, or external dictionary content fed to LLMs is mitigated (authoritative gate, clamped scores) but not solvable purely in this codebase (S4).
- **API keys in argv** remain visible in process listings if `--llm-api-key` is used — prefer env vars (S2).
- COMET model download has **no hash pinning** (S13); dependency versions are lower bounds, not pins.

**Linguistic / feature limitations (now disclosed in README)**
- Register detection, diacritization, transliteration, and gender agreement are heuristic placeholders (`detect_register` still counts "يا" as dialect; `check_gender_agreement` ignores `verb_form`) — real models are needed for production linguistics (F20 partial).
- Consistency tracking is limited to alias-vs-canonical registry checks.
- EPUB reconstruction is simplified (no images/CSS preservation); PDF output is text-only (`.txt`); PDF input is extraction-only.

## 7. End-user deployment checklist

1. `python -m venv .venv && source .venv/bin/activate`
2. `pip install -r requirements.txt`
3. Optional: `pip install openai ebooklib beautifulsoup4 python-docx pypdf` (and `unbabel-comet` for COMET-MQM — triggers a model download; NLTK `wordnet` corpus for dictionary skills: `python -m nltk.downloader wordnet`).
4. `export OPENAI_API_KEY=…` (or `ANTHROPIC_API_KEY`) — **never commit keys**; avoid `--llm-api-key` (argv exposure) and avoid putting keys in the tracked `config/translator.yaml`.
5. `python src/pipeline.py --source input.txt --target ar --output out.txt --use-llm` — without an LLM the output is a loudly-warned PLACEHOLDER, not a translation.
6. `python scripts/translate_book.py --input chapters/ --target ar --output out/` (add `--project-root` to keep registries/manifest outside the repo).
7. `pytest tests/` — 131 tests, no network needed. Dev tooling: `pip install -r requirements-dev.txt`.
8. Treat glossaries, source texts, and dictionary cache content as untrusted input (prompt-injection surface, S4); keep glossary files under 50 MB.
